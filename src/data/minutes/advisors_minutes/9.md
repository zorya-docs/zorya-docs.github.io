### 3. **Actions Page**
- **Action Types**: 
  - Two options for actions:
    - **Default Actions**: Common actions for all doctors in the same organization.
    - **Custom Actions**: Allow doctors to create custom actions (templates would be ideal to minimize the doctor's work).
  - **Endpoint**: Diogo suggested an endpoint to create custom actions, which makes sense.
  
- **Indexing and Lucene**:
  - Remove unnecessary parts of the code and leave only the indexer.
  - Lucene also runs because it is part of the chain, so indexing via Lucene happens as well.
  
- **User-Generated Actions**: 
  - How will users create actions? Example: Apply **GrandQC** to all studies with the tag "pulmon".
  - Actions in the database have an order and are tied to a user, but the focus should be on differentiating actions that run algorithms from other types.
  
- **Metadata Examples**: Patient name, manufacturer, description, model name, study date, etc.
  - The indexer should only run when images are uploaded.
  - Use common code that can be executed in multiple places to avoid redundancy.
